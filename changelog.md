## 4.0.0 - 2026-04-09
* Several breaking changes have been made to the Link bulk operation request types and exported enums.
**Removed exported types:** `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove any imports or usages of these types from your code.
**Removed request fields:** The optional `teamId` property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody` — the team is now inferred from context automatically.
**Removed enum value:** `InsulinInjection` (`"insulin_injection"`) has been removed from `IntervalTimeseriesExprTimeseries`.
**New enum values added:** `SonoraQuest` (`"sonora_quest"`) is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` has been added to `IndexColumnExprIndex`; and `apero` and `pverify` have been added to `PayorCodeExternalProvider`.
* The SDK now exposes three new resource namespaces: `compendium`, `labAccount`, and `orderTransaction`.
* The `labReport.parserCreateJob()` method now accepts an array of files (`core.file.Uploadable[]`) instead of a single file, enabling multi-file lab report uploads. **Migration:** wrap any existing single-file call in an array, e.g. `parserCreateJob([file], request)`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` instead of `AppointmentBookingRequest`. Callers must wrap their existing request body under the `body` key and may optionally supply `idempotencyKey` and `idempotencyError` headers.
* Several new optional parameters have also been added: `labSlug` on `getMarkers`, `orderTransactionId` on `getOrders`, `allowStale` on `getPscAppointmentAvailability`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* Several breaking changes have been made to request types in this release:
* The `teamId` field has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody`. Remove any usage of `teamId` from calls to `listBulkOps`, `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause`.
* The `address` field in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`. Update any code constructing this request to use `Vital.UserAddress`.
* In `connectManual`, the `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields are now sent as HTTP headers rather than in the request body; ensure these values are provided in the request object as before (the SDK handles the header mapping automatically).
* The SDK introduces three new resource clients: `client.compendium` (with `search` and `convert` methods), `client.labAccount` (with `getTeamLabAccounts`), and `client.orderTransaction`. Several `ResultMetadata` response fields (`patientFirstName`, `patientLastName`, `dob`, `labName`) changed from required `string` to optional `string | null`, which is a breaking change for consumers that access these fields without null checks. The `UserInfo` serializer now uses `UserAddress` instead of `Address`, and the `success` field on `UserRefreshErrorResponse`/`UserRefreshSuccessResponse` is now a boolean literal type (`false`/`true` respectively).
* The SDK now includes a new `OrderTransactionClient` (accessible via `client.orderTransaction`) with methods to retrieve order transactions (`getTransaction`), raw lab results (`getTransactionResult`), and PDF results (`getTransactionResultPdf`). New types for insulin injection timeseries, lab accounts, lab report parsing job events, order transactions, and expanded enum values for providers (`SonoraQuest`, `SamsungHealth`), order statuses (`Corrected`, `LabProcessingBlocked`), and sleep data (`recoveryReadinessScore`) are also available.
* The SDK now supports compendium search and convert endpoints with new types including `SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, and `ProviderIdConversionResponse`. New providers `TandemSource` and `SamsungHealth` have been added, along with `Apero` and `Pverify` payor code providers. Several address types now support an optional `accessNotes` field, appointment booking requests support optional notes and async confirmation settings, and new order transaction types (`OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`) are available for richer order management.
* The SDK now includes support for insulin pump as a device source type across all relevant source type enums. New types are available for order transactions (`ClientFacingOrderTransaction`, `OrderTransactionStatus`, `OrderOrigin`, `OrderSummary`, `GetOrderTransactionResponse`), lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`, `GetTeamLabAccountsResponse`), lab report parsing job webhook events (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`), and compendium conversion (`CompendiumSearchLabs`, `ConvertCompendiumResponse`). Existing models have been enriched with new optional fields: `ClientFacingOrder` gains `last_event`, `clinical_notes`, `origin`, and `order_transaction`; `ClientFacingOrderEvent` gains `status_detail`; `ClientFacingInsulinInjectionSample` gains `delivery_mode`, `delivery_form`, and `bolus_purpose`; and `ClientFacingSleep` gains `recovery_readiness_score`.
* The SDK now includes support for compendium search (`SearchCompendiumResponse`, `SearchMode`, `PerLabCandidate`, `RelatedCandidate`, `CanonicalCandidate`), lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), and order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`). New providers `tandem_source` and `samsung_health` are now available in the `Providers` enum, and address types (`PatientAddress`, `UsAddress`, `UserAddress`) now support an optional `accessNotes` field. Additional query expression types (`AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`) are available for use in select and group-by queries.
