## 4.0.0 - 2026-04-02
* Several breaking changes have been made to the Link bulk-operation request types and exported enum types:
* The `teamId` optional property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any `teamId` field from objects passed to the corresponding methods.
* The exported enum types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove any imports or references to these types.
* `insulin_injection` has been removed from the `IntervalTimeseriesExprTimeseries` enum.
* New enum values have also been added: `sonora_quest` in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` in `IndexColumnExprIndex`; and `apero` and `pverify` in `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob()` method now accepts an array of files (`Uploadable[]`) instead of a single file (`Uploadable`), enabling multi-file lab report uploads. Update all existing call sites to wrap the single file argument in an array (e.g. `parserCreateJob([file], request)`).
* Three new resource namespaces are now available on the client: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object instead of `AppointmentBookingRequest` directly. Callers must wrap the existing booking request in a `body` field (e.g. `{ body: { bookingKey: "..." } }`) and may optionally provide `idempotencyKey` and `idempotencyError` headers. Several other endpoints have gained new optional parameters: `getPscAppointmentAvailability` supports `allowStale`, `getMarkers` supports `labSlug`, `getOrders` supports `orderTransactionId`, and `CreateOrderRequestCompatible` now includes an optional `clinicalNotes` field.
* The `teamId` field has been removed from the following request types: `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody`. Callers that set `teamId` on these requests must remove that field. Additionally, the `address` field on `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress` — update any code constructing this request to use the `UserAddress` type.
* Several type refinements and new fields are now available across the SDK:
* **`ClientFacingInsulinInjectionSample`** gains three new optional fields — `deliveryMode`, `deliveryForm`, and `bolusPurpose` — to represent insulin delivery details.
* **`ParsingJob`** no longer includes the `jobId` field (breaking removal) and now includes an optional `failureReason` field.
* **`ResultMetadata`** fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional; a new optional `gender` field has been added.
* **`UserInfo.address`** type has changed from `Address` to `UserAddress`.
* Boolean fields on `ClientFacingActivity`, `ClientFacingProfile`, `HistoricalPullCompleted`, `Placeholder`, `UserRefreshErrorResponse`, and `UserRefreshSuccessResponse` have been narrowed to literal types (`true` or `false`).
* New enum values added: `Labs` (`sonora_quest`, `crl`), `ManualProviders` (`samsung_health`), `PasswordProviders` (`tandem_source`), `OrderStatus` (corrected statuses and `lab_processing_blocked`), `OrderLowLevelStatus` (`corrected`, `lab_processing_blocked`).
* A new `compendium` resource is now available in the serialization layer.
* `ManualConnectionData` gains an optional `grantedPermissions` field.
* The SDK now exposes three new resource clients on `VitalClient`: `compendium` (with `search()` and `convert()` methods for lab test compendium operations), `labAccount` (with `getTeamLabAccounts()`), and `orderTransaction`. Several existing types have been updated: `ResultMetadata` patient identity fields (`patientFirstName`, `patientLastName`, `dob`, `labName`) are now optional and a new optional `gender` field has been added; `UserInfo.address` now uses the `UserAddress` type instead of `Address`; and `UserRefreshErrorResponse.success` / `UserRefreshSuccessResponse.success` are now narrowed to literal `false` / `true` types respectively.
* The SDK now includes a new `orderTransaction` resource on the client with `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` methods for retrieving order transaction details and results.
* Numerous new types and enum values have been added: insulin injection timeseries support (`InsulinInjectionTimeseriesExpr` and related types), sleep readiness tracking (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, `recoveryReadinessScore` on `ClientFacingSleep`), lab account management (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), order lifecycle fields (`OrderOrigin`, `OrderStatusDetail`, `lastEvent` and `orderTransaction` on `ClientFacingOrder`), new appointment booking options (async confirmation fields), and new enum values across `AppointmentProvider`, `Labs`, `OrderStatus`, `ManualProviders`, and source type enums.
* The SDK now supports compendium search and conversion with new types `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, and `RelatedCandidate`. New order transaction types (`OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`) and lab account types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`) have been added. Additional capabilities include new query expression types (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, `InsulinInjectionTimeseriesExpr`), optional `accessNotes` on address types, optional `appointmentNotes` on appointment request/response types, new provider values (`TandemSource`, `SamsungHealth`), and new payor code providers (`Apero`, `Pverify`).
* The SDK now supports insulin pump as a device source type across all relevant source type enums. Several new types have been added: order transaction tracking (`ClientFacingOrderTransaction`, `OrderTransactionStatus`, `OrderOrigin`), lab account management (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`, `GetTeamLabAccountsResponse`), lab report parsing job webhook events, and compendium conversion responses (`ConvertCompendiumResponse`, `CompendiumSearchLabs`). New optional fields have also been added to `ClientFacingOrder` (`clinical_notes`, `last_event`, `origin`, `order_transaction`), `ClientFacingOrderEvent` (`status_detail`), `ClientFacingSleep` (`recovery_readiness_score`), and `ClientFacingInsulinInjectionSample` (`delivery_mode`, `delivery_form`, `bolus_purpose`).
* The SDK now supports several new types and capabilities. New optional `access_notes` field is available on `PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`, and the new `UserAddress` type. Two new providers — `tandem_source` and `samsung_health` — have been added to the `Providers` enum. New types for lab compendium search (`SearchCompendiumResponse`, `SearchMode`, `PerLabCandidate`, `RelatedCandidate`, `CanonicalCandidate`), order transactions (`ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`, `OrderTransactionStatus`), lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`), and additional query expression types (`AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`) are now available.
