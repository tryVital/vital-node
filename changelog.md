## 4.0.0 - 2026-04-10
* Several breaking changes have been made to Link and timeseries types:
* The `teamId` optional property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any references to `teamId` in calls to these bulk Link operations.
* The exported types and constants `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from the SDK. Update any code that imports or references these symbols.
* The `InsulinInjection` (`"insulin_injection"`) value has been removed from the `IntervalTimeseriesExprTimeseries` enum.
* New enum values have also been added: `sonora_quest` to `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` to `IndexColumnExprIndex`; and `apero` and `pverify` to `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob` method now accepts an array of files (`core.file.Uploadable[]`) instead of a single file (`core.file.Uploadable`), enabling multi-file upload. Callers must update their code to wrap the file argument in an array: `parserCreateJob([file], request)`.
* Three new resource modules are now available on the SDK client: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method now accepts a `LabTestsBookPscAppointmentRequest` object instead of `AppointmentBookingRequest` directly, enabling optional idempotency headers (`x-idempotency-key`, `x-idempotency-error`) to be passed alongside the booking body. Several new optional fields have also been added: `clinicalNotes` on `CreateOrderRequestCompatible`, `labSlug` on `LabTestsGetMarkersRequest`, `orderTransactionId` on the get-orders request, and `allowStale` on `LabTestsGetPscAppointmentAvailabilityRequest`.
* The `teamId` property has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody` — callers passing this field should remove it. The `address` property in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`; update any code constructing this object accordingly. The `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields on `ManualConnectionData` are now transmitted as HTTP headers rather than body fields.
* Several breaking type changes have been made to SDK interfaces:
* `ResultMetadata.patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (previously required) — existing code that accesses these without null checks may encounter runtime issues.
* `ParsingJob.jobId` (previously required `string`) has been removed; a new optional `failureReason` field is added.
* `UserInfo.address` type has changed from `Address` to `UserAddress` — update type annotations accordingly.
* `wheelchairUse` on `ClientFacingActivity` and `ClientFacingProfile` has been narrowed from `boolean` to `true`; `HistoricalPullCompleted.isFinal` narrowed to `true`; `UserRefreshSuccessResponse.success` narrowed to `true`; `UserRefreshErrorResponse.success` narrowed to `false`; `Placeholder.placeholder` narrowed to `true`.
* New additions include: `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields on `ClientFacingInsulinInjectionSample`; new `OrderStatus` values (`sample_with_lab.testkit.lab_processing_blocked`, `completed.*.corrected`); new lab values `sonora_quest` and `crl`; new provider values `samsung_health` and `tandem_source`; and a new `compendium` serialization resource.
* Three new resource clients are now available on `VitalClient`: `compendium` (with `search()` and `convert()` methods for lab test compendium lookup and cross-lab conversion), `labAccount` (with `getTeamLabAccounts()`), and `orderTransaction`. Several existing request types have been extended with new optional fields, including `labAccountId`/`labSlug` on `CreateLabTestRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, `appointmentNotes` on `RequestAppointmentRequest`, and `grantedPermissions`/SDK version fields on `ManualConnectionData`. The `ResultMetadata` type now includes an optional `gender` field, and previously required fields (`patientFirstName`, `patientLastName`, `dob`, `labName`) are now optional.
* The SDK now includes a new `OrderTransactionClient` (accessible via `client.orderTransaction`) with methods to retrieve order transactions (`getTransaction`), raw lab results (`getTransactionResult`), and PDF results (`getTransactionResultPdf`). Many new types have been added including support for insulin injection timeseries, derived readiness metrics, lab accounts, Sonora Quest as a lab/appointment provider, and order transaction tracking embedded in orders and lab results. Existing types such as `ClientFacingOrder`, `ClientFacingAppointment`, `AppointmentBookingRequest`, `ClientFacingSleep`, and `LabResultsRaw` have been extended with new optional fields.
* The SDK now supports compendium search and conversion endpoints with new types (`SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`). New providers `TandemSource` and `SamsungHealth` are available in the `Providers` enum, `Apero` and `Pverify` in `PayorCodeExternalProvider`, and new enums `ParsingJobFailureReason`, `SearchMode`, `UsState`, and `ResultMetadataGender` have been added. Several existing types gain new optional fields including `accessNotes` on address types, `appointmentNotes` on appointment requests and `ClientFacingAppointment`, and `clinicalNotes` on order requests, along with new order transaction and lab account management types.
* The SDK now supports insulin pump as a data source type across ECG, menstrual cycle, and sleep cycle resources. New optional fields (`deliveryMode`, `deliveryForm`, `bolusPurpose`) have been added to `ClientFacingInsulinInjectionSample`, and a `recoveryReadinessScore` field is now available on `ClientFacingSleep`. Order management has been expanded with order transaction tracking (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), order origin and status detail fields, and new lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`). Additional new types include lab report parsing job events, compendium conversion responses, and readiness/timeseries expression models.
* The SDK now includes a large set of new types and capabilities. New provider values `tandem_source` and `samsung_health` are available in the `Providers` enum. Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now support an optional `access_notes` field. Numerous new types have been added including lab compendium search (`SearchCompendiumResponse`, `SearchMode`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`), order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), derived readiness metrics, insulin injection timeseries expressions, and US state enumeration (`UsState`).
