## 4.0.0 - 2026-04-01
* Several breaking changes have been made to the Link bulk operation request types and exported enums.
**Removed exported types:** `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from the SDK. Any code referencing these types must be updated.
**Removed request fields:** The optional `teamId` property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody` — remove any usages of this field from bulk operation calls.
**Removed enum value:** `InsulinInjection` (`"insulin_injection"`) has been removed from `IntervalTimeseriesExprTimeseries` — update any exhaustive checks or references to this value.
**New enum values added:** `SonoraQuest` (`"sonora_quest"`) is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `DerivedReadiness` (`"derived_readiness"`) has been added to `IndexColumnExprIndex`; and `apero` and `pverify` have been added to `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob()` method now accepts an array of files (`file: core.file.Uploadable[]`) instead of a single file, enabling multi-file parse jobs. Callers must update their code to wrap the existing single file in an array (e.g. `parserCreateJob([file], request)`).
* Three new resource namespaces are now available on the client: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts `LabTestsBookPscAppointmentRequest` (instead of `AppointmentBookingRequest`) which wraps the booking body and adds optional `idempotencyKey` and `idempotencyError` header fields. Several endpoints have gained new optional parameters: `labSlug` on `getMarkers`, `orderTransactionId` on `getOrders`, `allowStale` on `getPscAppointmentAvailability`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* Several breaking changes have been made to request types in this release:
* The `teamId` property has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody`. Remove any `teamId` usage from calls to `listBulkOps`, `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause`.
* The `address` field in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`. Update any code constructing this request to use a `Vital.UserAddress` value.
* `ManualConnectionData` now accepts `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields, which are sent as HTTP headers rather than body properties.
* The SDK introduces three new resource clients: `client.compendium` (with `search()` and `convert()` methods), `client.labAccount` (with `getTeamLabAccounts()`), and `client.orderTransaction`. Several breaking changes are also included: `ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` have changed from required `string` to optional `string | null`, requiring callers to add null checks; `UserInfo.address` now uses `UserAddress` instead of `Address`; and `UserRefreshErrorResponse.success` / `UserRefreshSuccessResponse.success` have been narrowed to literal types `false` and `true` respectively, which may break exhaustive type checks on `boolean`.
* The SDK now includes a new `orderTransaction` resource on the client with `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` methods for working with order transactions. New types have been added for lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), insulin injection timeseries, derived readiness columns, order origins, and order status details. Several existing types have been extended with new optional fields, and new enum values have been added to `AppointmentProvider`, `Labs`, `ManualProviders`, `OrderLowLevelStatus`, `OrderStatus`, and device source type enums.
* The SDK now includes expanded provider support with `TandemSource` added to `PasswordProviders` and `Providers`, and `SamsungHealth` added to `Providers`, along with `Apero` and `Pverify` added to `PayorCodeExternalProvider`. New types have been introduced including `OrderSummary`, `OrderTransactionStatus`, `UsState`, `UserAddress`, `SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, and more to support compendium search and order transaction workflows. Several address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now support an optional `accessNotes` field, and appointment booking/rescheduling requests support optional `appointmentNotes` and async confirmation fields.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New order transaction tracking types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderSummary`, `OrderOrigin`) have been added, along with new optional fields on `ClientFacingOrder` (`clinicalNotes`, `lastEvent`, `origin`, `orderTransaction`) and `ClientFacingOrderEvent` (`statusDetail`). Additional new types include lab account management (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), lab report parsing job events, compendium conversion helpers, and insulin injection delivery metadata fields (`deliveryMode`, `deliveryForm`, `bolusPurpose`) on `ClientFacingInsulinInjectionSample`.
* The SDK now supports a broad set of new capabilities: compendium search (`SearchCompendiumResponse`, `SearchMode`, `PerLabCandidate`, `RelatedCandidate`, `CanonicalCandidate`), lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), order transactions (`ClientFacingOrderTransaction`, `OrderTransactionStatus`, `OrderSummary`), and insulin injection timeseries query expressions (`InsulinInjectionTimeseriesExpr`). Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now include an optional `accessNotes` field, and two new providers — `tandem_source` and `samsung_health` — have been added to the `Providers` enum.
