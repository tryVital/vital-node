## 4.0.0 - 2026-04-03
* Several breaking changes have been made to the Link resource types. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed — update any code that references these types. The optional `teamId` property has also been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Additionally, the `InsulinInjection` value has been removed from the `IntervalTimeseriesExprTimeseries` enum. New enum values have been added: `sonora_quest` in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` in `IndexColumnExprIndex`; and `apero` and `pverify` in `PayorCodeExternalProvider`.
* The `parserCreateJob` method on `LabReportClient` now accepts an array of files (`core.file.Uploadable[]`) instead of a single file, enabling multi-file lab report parsing jobs. Callers must wrap their existing single file in an array (e.g. `[file]`).
* Three new resource namespaces are now available on the SDK client: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object (instead of `AppointmentBookingRequest` directly), enabling optional idempotency headers (`idempotencyKey`, `idempotencyError`) to be passed alongside the booking body. Several new optional request parameters have been added: `labSlug` on `getMarkers`, `allowStale` on `getPscAppointmentAvailability`, `orderTransactionId` on `getOrders`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* Several breaking changes have been made to request types in this release:
* The `teamId` field has been removed from `LinkListBulkOpsRequest` and from the body of `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause` requests — remove any `teamId` usage from these call sites.
* `UserInfoCreateRequest.address` now expects a `Vital.UserAddress` instead of `Vital.Address` — update any objects passed to this field.
* `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields on `ManualConnectionData` are now sent as HTTP headers rather than request body fields; existing consumers passing these values in the body should remove them (the SDK handles header injection automatically).
* Several breaking changes have been introduced in this release:
* **`ParsingJob`**: The required `jobId` field has been removed. Update any code that reads `parsingJob.jobId`. A new optional `failureReason` field has been added.
* **`ResultMetadata`**: The fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`). Existing code that accesses these fields without null checks may encounter runtime issues. A new optional `gender` field has been added.
* **`UserInfo.address`**: The type has changed from `Address` to `UserAddress`. Update type annotations and imports accordingly.
* **Boolean literal narrowing**: `wheelchairUse` (on `ClientFacingActivity` and `ClientFacingProfile`), `isFinal` (on `HistoricalPullCompleted`), `Placeholder.placeholder`, `UserRefreshSuccessResponse.success`, and `UserRefreshErrorResponse.success` have been narrowed from `boolean` to literal types (`true` or `false`). Code performing exhaustive checks on these fields may need adjustment.
* New additions include delivery fields on `ClientFacingInsulinInjectionSample`, new lab/provider/order status enum values (`sonora_quest`, `crl`, `samsung_health`, `tandem_source`, `corrected`, `lab_processing_blocked`), and a new compendium serialization module.
* The SDK now exposes three new resource clients on `VitalClient`: `compendium` (with `search()` and `convert()` methods for lab test compendium lookup and cross-lab conversion), `labAccount` (with `getTeamLabAccounts()` for retrieving team lab accounts), and `orderTransaction`. Several existing request types have been extended with new optional fields, including `labAccountId`/`labSlug` on `CreateLabTestRequest`, `labSlug` on `LabTestsGetMarkersRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, `appointmentNotes` on `RequestAppointmentRequest`, and `vitalIosSdkVersion`/`vitalAndroidSdkVersion`/`grantedPermissions` on `ManualConnectionData`. The `success` field on `UserRefreshErrorResponse` and `UserRefreshSuccessResponse` is now typed as the literal `false` and `true` respectively, providing stronger type discrimination.
* The SDK now includes a new `OrderTransactionClient` (accessible via `client.orderTransaction`) with methods to retrieve order transactions (`getTransaction`), their raw results (`getTransactionResult`), and PDF results (`getTransactionResultPdf`).
* Numerous new types and enum values have been added: order transaction types (`ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`), lab account types (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), insulin injection timeseries types, derived readiness column expressions, and lab report parsing job event types. Existing types such as `ClientFacingOrder`, `ClientFacingAppointment`, `AppointmentBookingRequest`, `ClientFacingSleep`, and several source-type enums have also been expanded with new optional fields and enum values.
* The SDK now includes a range of new types and capabilities. Compendium search and conversion are supported via `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. Order management is extended with `OrderSummary`, `OrderTransactionStatus`, `OrderOrigin`, and `OrderStatusDetail`. New providers `TandemSource` and `SamsungHealth` are available in `Providers`, and `Apero`/`Pverify` have been added to `PayorCodeExternalProvider`. Existing address types (`PatientAddress`, `UsAddress`, `UserAddress`, etc.) and appointment request types now accept an optional `accessNotes` or `appointmentNotes` field, and query expressions gain support for `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New optional fields have been added to `ClientFacingInsulinInjectionSample` (`deliveryMode`, `deliveryForm`, `bolusPurpose`), `ClientFacingSleep` (`recoveryReadinessScore`), and `ClientFacingOrder` (`clinicalNotes`, `lastEvent`, `origin`, `orderTransaction`). New types for lab order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), lab report parsing job events (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`), and compendium conversion (`ConvertCompendiumResponse`, `CompendiumSearchLabs`) are now available.
* The SDK now includes new address field `accessNotes` on `PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, and `UsAddress` types, as well as a new `UserAddress` type. Two new providers (`tandem_source` and `samsung_health`) are now supported in the `Providers` enum. A suite of new types for compendium search (`SearchCompendiumResponse`, `SearchMode`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`), lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`), order transactions (`ClientFacingOrderTransaction`, `OrderTransactionStatus`), lab report parsing (`ParsingJobFailureReason`), and query expressions (`AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`) are also available.
