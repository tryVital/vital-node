## 4.0.0 - 2026-04-03
* Several breaking changes are included in this release:
* The `teamId` optional property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any references to `teamId` in code that constructs these request objects.
* The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed. Update any imports or usages of these types accordingly.
* `IntervalTimeseriesExprTimeseries` no longer includes the `insulin_injection` value.
* New enum values have also been added: `sonora_quest` to `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` to `IndexColumnExprIndex`; and `apero` and `pverify` to `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob` method now accepts an array of `Uploadable` files (`core.file.Uploadable[]`) instead of a single file, enabling multi-file lab report parsing jobs. Callers must update their code to wrap the single file argument in an array (e.g. `parserCreateJob([file], request)`).
* Three new resource namespaces are now available on the SDK client: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method now accepts a `LabTestsBookPscAppointmentRequest` object (instead of a bare `AppointmentBookingRequest`) to support idempotency headers (`idempotencyKey`, `idempotencyError`) and a `body` wrapper. Several new optional parameters have been added: `allowStale` on `getPscAppointmentAvailability`, `labSlug` on `getMarkers`, `orderTransactionId` on `getOrders`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* The `teamId` optional property has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody` — callers passing `teamId` will need to remove it from their request objects.
* The `address` field type in `UserInfoCreateRequest` has changed from `Vital.Address` to `Vital.UserAddress`; update any type annotations or object constructions that referenced `Vital.Address` in this context.
* Several breaking type changes and new fields have been introduced in this release.
**Breaking changes:**
* `ParsingJob.jobId` (required `string`) has been removed; a new optional `failureReason` field is added in its place.
* `UserInfo.address` now has type `UserAddress` instead of `Address`.
* `ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (were previously required); a new optional `gender` field has been added.
* `wheelchairUse` on `ClientFacingActivity` and `ClientFacingProfile` is now typed as `true` (literal) instead of `boolean`; similarly `isFinal` on `HistoricalPullCompleted`, `success` on `UserRefreshErrorResponse`/`UserRefreshSuccessResponse`, and `placeholder` on `Placeholder` are now literal types.
**New additions:**
* `ClientFacingInsulinInjectionSample` gains three new optional fields: `deliveryMode`, `deliveryForm`, and `bolusPurpose`.
* New `Labs` values: `sonora_quest`, `crl`. New `ManualProviders` value: `samsung_health`. New `PasswordProviders` value: `tandem_source`.
* New `OrderStatus` values for corrected completions and lab-processing-blocked states across all order types.
* New `compendium` serialization namespace is now exported.
* The SDK now exposes three new resource clients on `VitalClient`: `compendium` (with `search()` and `convert()` methods for lab compendium lookups), `labAccount` (with `getTeamLabAccounts()`), and `orderTransaction`. Several existing request types have been expanded with new optional fields, including `labAccountId`/`labSlug` on `CreateLabTestRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, `appointmentNotes` on `RequestAppointmentRequest`, and `grantedPermissions`/SDK version fields on `ManualConnectionData`. The `success` field on `UserRefreshSuccessResponse` and `UserRefreshErrorResponse` is now typed as a boolean literal (`true` or `false` respectively) instead of `boolean`.
* The SDK now includes a new `orderTransaction` client (`client.orderTransaction`) with methods to retrieve order transactions (`getTransaction`), raw lab results (`getTransactionResult`), and PDF results (`getTransactionResultPdf`). New types for insulin injection timeseries, lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), order origins, order status details, and readiness/recovery analytics (`DerivedReadinessColumnExpr`) have been added. Several existing types have been expanded with new optional fields including appointment notes, async confirmation options, `recoveryReadinessScore` on sleep data, and transaction references on orders and lab results. New `SonoraQuest` lab and `SamsungHealth` provider enum values are also available.
* The SDK now supports compendium search and conversion with new `SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ConvertCompendiumResponse` types. New providers `TandemSource` and `SamsungHealth` are available in `Providers`, and `Apero`/`Pverify` have been added to `PayorCodeExternalProvider`. Address types (`PatientAddress`, `UsAddress`, `UserAddress`, and others) now support an optional `accessNotes` field, appointment types support optional `appointmentNotes` and async confirmation options, and query expression unions (`QuerySelectItem`, `QueryGroupByItem`) now include `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New types and fields have been added for order transaction management (`ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`), lab account administration (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), compendium search and conversion (`CompendiumSearchLabs`, `ConvertCompendiumResponse`), lab report parsing job events, and insulin injection delivery metadata (`delivery_mode`, `delivery_form`, `bolus_purpose`). The `ClientFacingSleep` type now includes an optional `recovery_readiness_score` field, and `ClientFacingOrder` gains `clinical_notes`, `last_event`, `origin`, and `order_transaction` fields.
* The SDK now includes support for several new capabilities:
* Two new providers (`tandem_source` and `samsung_health`) are available in the `Providers` enum.
* Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now include an optional `accessNotes` field.
* New compendium search types are available: `SearchCompendiumResponse`, `SearchMode`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`, and others.
* New lab account management types (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`, `GetTeamLabAccountsResponse`) and order transaction types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderTransactionStatus`) have been added.
* Query expressions now support `InsulinInjectionTimeseriesExpr`, `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and a `recovery_readiness_score` sleep column.
