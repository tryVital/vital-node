## 4.0.0 - 2026-04-08
* Several breaking changes have been made to the Link bulk operation request types and enum values:
**Removed properties:** The optional `teamId` field has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any references to `teamId` in your code.
**Removed types:** The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove any imports of these types.
**Removed enum value:** `IntervalTimeseriesExprTimeseries.InsulinInjection` (`"insulin_injection"`) has been removed from the enum. Update any exhaustive checks or usages accordingly.
**New enum values added:** `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs` now include `"sonora_quest"` (`SonoraQuest`); `IndexColumnExprIndex` now includes `"derived_readiness"`; and `PayorCodeExternalProvider` now includes `"apero"` and `"pverify"`.
* The `labReport.parserCreateJob` method now accepts an array of files (`core.file.Uploadable[]`) instead of a single file, enabling multiple files to be uploaded in a single parse job. **Migration:** wrap existing single-file calls in an array, e.g. change `parserCreateJob(file, request)` to `parserCreateJob([file], request)`.
* Three new resource namespaces are now available on the client: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method now accepts a `LabTestsBookPscAppointmentRequest` object instead of `AppointmentBookingRequest` directly. Callers must wrap the booking payload under a `body` key and may optionally supply `idempotencyKey` and `idempotencyError` fields. For example:
* ```ts
* // Before
* await client.labTests.bookPscAppointment(orderId, { bookingKey: "..." });
* // After
* await client.labTests.bookPscAppointment(orderId, { body: { bookingKey: "..." } });
* ```
* Additionally, several new optional parameters are available: `allowStale` on `getPscAppointmentAvailability`, `labSlug` on `getMarkers`, `orderTransactionId` on `getOrders`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* The `teamId` field has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody` — remove any `teamId` usage from calls to `listBulkOps`, `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause`. Additionally, the `address` field in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress` — update any code passing an `Address` object to use `UserAddress` instead.
* Several breaking type changes have been introduced in this release:
* **`ParsingJob.jobId`** (a required `string` field) has been removed and replaced with the optional `failureReason` field. Update any code that reads `job.jobId`.
* **`UserInfo.address`** type has changed from `Address` to `UserAddress`. Update type annotations accordingly.
* **`ResultMetadata`** fields `patientFirstName`, `patientLastName`, `dob`, and `labName` have changed from required to optional (`string` → `string | undefined`). Add null checks where these values are accessed.
* Several `boolean` fields have been narrowed to literal types: `wheelchairUse` on `ClientFacingActivity` and `ClientFacingProfile` is now `true | undefined`; `isFinal` on `HistoricalPullCompleted` is now `true`; `success` on `UserRefreshErrorResponse` is now `false` and on `UserRefreshSuccessResponse` is now `true`. Code assigning `false` to these fields or expecting a general `boolean` may need to be updated.
* New additions include `deliveryMode`, `deliveryForm`, and `bolusPurpose` optional fields on `ClientFacingInsulinInjectionSample`; new `compendium` serialization namespace; new provider and order status enum values (`samsung_health`, `tandem_source`, `sonora_quest`, `crl`, `corrected`, `lab_processing_blocked`); and `grantedPermissions` on `ManualConnectionData`.
* The SDK now exposes three new resource clients on `VitalClient`: `compendium` (with `search()` and `convert()` methods for lab test discovery and cross-lab conversion), `labAccount` (with `getTeamLabAccounts()` for retrieving team lab account configurations), and `orderTransaction`. Several existing request types have been extended with new optional fields, including `labAccountId`/`labSlug` on `CreateLabTestRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, `appointmentNotes` on `RequestAppointmentRequest`, and `grantedPermissions`/SDK version fields on `ManualConnectionData`. `ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional and a new `gender` field has been added.
* The SDK now supports order transactions via a new `client.orderTransaction` resource with `getTransaction()`, `getTransactionResult()`, and `getTransactionResultPdf()` methods. New types have been added for lab accounts, insulin injection timeseries, order origins, order status details, lab report parsing job events, and derived readiness analytics. Several existing types (`ClientFacingOrder`, `ClientFacingAppointment`, `AppointmentBookingRequest`, `ClientFacingSleep`, `Address`, and more) have been expanded with new optional fields. New enum values have been added to `AppointmentProvider`, `Labs`, `ClientFacingLabs`, `ManualProviders`, `OrderStatus`, `OrderLowLevelStatus`, and multiple source type enums.
* The SDK now supports compendium search and conversion with new `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, and related types. Order transaction management is now available via `ClientFacingOrderTransaction`, `OrderSummary`, and `GetOrderTransactionResponse`. New providers `TandemSource` and `SamsungHealth` have been added, along with new optional `accessNotes` fields on address types, optional `appointmentNotes` on appointment request types, and expanded query expression support for `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New order transaction tracking types (`ClientFacingOrderTransaction`, `OrderTransactionStatus`, `OrderOrigin`, `OrderStatusDetail`) have been added, along with new fields on `ClientFacingOrder` (`clinical_notes`, `last_event`, `origin`, `order_transaction`) and `ClientFacingOrderEvent` (`status_detail`). Lab account management types (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`, `GetTeamLabAccountsResponse`) and lab report parsing job event types are now available. Additional new types include compendium conversion responses, derived readiness analytics expressions, insulin injection timeseries expressions, and a `recovery_readiness_score` field on sleep data.
* The SDK now supports several new data types and capabilities. New provider values `tandem_source` and `samsung_health` are available in the `Providers` enum. Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now include an optional `access_notes` field. New types for lab compendium search (`SearchCompendiumResponse`, `SearchMode`, `PerLabCandidate`, `RelatedCandidate`, `CanonicalCandidate`), order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), insulin injection timeseries expressions, derived readiness column expressions, and US state enumeration (`UsState`) are also available.
