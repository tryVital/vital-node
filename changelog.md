## 4.0.0 - 2026-04-02
* The `parserCreateJob` method on `LabReportClient` now accepts an array of files (`file: core.file.Uploadable[]`) instead of a single file, enabling multi-file uploads in a single parse job. Callers passing a single `Uploadable` must now wrap it in an array (e.g., `[file]`). Three new resource namespaces — `compendium`, `labAccount`, and `orderTransaction` — are now available on the client.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object (instead of `AppointmentBookingRequest` directly), which wraps the booking body and adds optional `idempotencyKey` and `idempotencyError` header fields. Several new optional parameters have also been added: `labSlug` on `getMarkers`, `orderTransactionId` on `getOrders`, `allowStale` on `getPscAppointmentAvailability`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* Several breaking changes have been made to request types in this release:
* The `teamId` field has been removed from `LinkListBulkOpsRequest` and the bulk operation request bodies (`BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, `BulkPauseConnectionsBody`). Remove any `teamId` usage from calls to `link.listBulkOps()`, `link.bulkImport()`, `link.bulkTriggerHistoricalPull()`, `link.bulkExport()`, and `link.bulkPause()`.
* The `address` field in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`. Update any code that constructs or passes this request object accordingly.
* The `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields are now sent as HTTP headers rather than body fields when calling `link.connectManualProvider()`; the public `ManualConnectionData` type reflects this change.
* Several breaking changes have been introduced in this release:
* **`ParsingJob.jobId` removed**: The required `jobId` field has been removed from the `ParsingJob` type. Remove any references to `parsingJob.jobId` in your code. A new optional `failureReason` field has been added.
* **`UserInfo.address` type changed**: The `address` field now uses `UserAddress` instead of `Address`. Update any code that constructs or reads this field accordingly.
* **Boolean fields narrowed to literal types**: `HistoricalPullCompleted.isFinal`, `UserRefreshSuccessResponse.success`, `UserRefreshErrorResponse.success`, `ClientFacingActivity.wheelchairUse`, `ClientFacingProfile.wheelchairUse`, and `Placeholder.placeholder` have been narrowed from `boolean` to specific literal types (`true` or `false`). Exhaustive type checks on these fields may need to be updated.
* **`ResultMetadata` fields made optional**: `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional — add null checks where these are accessed.
* New capabilities also included: additional optional fields on `ClientFacingInsulinInjectionSample` (`deliveryMode`, `deliveryForm`, `bolusPurpose`), new lab/provider/order status enum values (`sonora_quest`, `crl`, `samsung_health`, `tandem_source`, `corrected`, `lab_processing_blocked`), and a new `compendium` serialization resource.
* The `ResultMetadata` type has breaking changes: `patientFirstName`, `patientLastName`, `dob`, and `labName` were previously required fields and are now optional (`string | null | undefined`). Code that accesses these properties without null-checks will need to be updated.
* The `UserInfo` serializer now uses `UserAddress` instead of `Address` for the `address` field — callers relying on the `Address.Raw` type for this field must migrate to `UserAddress.Raw`. The `success` field on `UserRefreshSuccessResponse` is narrowed to the literal `true` and on `UserRefreshErrorResponse` to `false`.
* New capabilities are also available: `client.compendium` exposes `search()` and `convert()` methods for lab compendium operations; `client.labAccount` exposes `getTeamLabAccounts()`; and `client.orderTransaction` is now accessible on the main `VitalClient`.
* The SDK now includes a new `orderTransaction` client with `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` methods for retrieving order transaction details and lab results. New types for insulin injection timeseries data, lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), lab report parsing job events, and order transactions (`ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`) have been added. Existing types such as `ClientFacingOrder`, `ClientFacingAppointment`, `AppointmentBookingRequest`, and `ClientFacingSleep` have been extended with new optional fields, and several enums have new values including `SonoraQuest`, `SamsungHealth`, `InsulinPump`, and new order statuses.
* The SDK now includes a broad set of new types and capabilities. New compendium search and convert support is available via `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, and related types (`CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`, `SearchMode`). New providers `TandemSource` and `SamsungHealth` have been added, along with `Apero` and `Pverify` in `PayorCodeExternalProvider`. Several address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`, `UserAddress`) now support an optional `accessNotes` field. Query expression unions (`QueryGroupByItem`, `QuerySelectItem`, `AggregateExprArg`) are extended with `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`. Additional optional fields have been added to appointment and order request/response types.
* The SDK now supports insulin pump as a device source type across all relevant source type enums (`DeviceSourceType`, `ElectrocardiogramSourceType`, `MenstrualCycleSourceType`, `SleepCycleSourceType`). Insulin injection samples have three new optional fields: `deliveryMode`, `deliveryForm`, and `bolusPurpose`. Orders now include `clinicalNotes`, `lastEvent`, `origin`, and `orderTransaction` fields, and order events include a `statusDetail` field. New types are available for order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), lab report parsing job events, compendium conversion responses, and derived readiness/insulin injection timeseries expressions.
* The SDK now includes a wide range of new types and capabilities. New providers `tandem_source` and `samsung_health` are available in the `Providers` enum. Address types (`PatientAddress`, `UsAddress`, `UserAddress`, and variants) now support an optional `access_notes` field. New types for compendium search (`SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `SearchMode`), lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`), order transactions (`ClientFacingOrderTransaction`, `OrderTransactionStatus`), and insulin injection details are now available. Query expressions now support `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr` in select and group-by operations.
