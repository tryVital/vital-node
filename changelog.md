## 4.0.0 - 2026-04-02
* The following exported types have been removed from the SDK: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`. The `teamId` optional property has also been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody` — remove any usage of these fields from your code. Additionally, `insulin_injection` has been removed from the `IntervalTimeseriesExprTimeseries` enum. New values have been added: `sonora_quest` in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `apero` and `pverify` in `PayorCodeExternalProvider`; and `derived_readiness` in `IndexColumnExprIndex`.
* The `parserCreateJob` method on `LabReportClient` now accepts an array of files (`core.file.Uploadable[]`) instead of a single file, enabling multiple files to be uploaded in one parse job. Existing callers must wrap their single file argument in an array (e.g. `[file]`). Three new resource modules — `compendium`, `labAccount`, and `orderTransaction` — are now available on the SDK client.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` instead of `AppointmentBookingRequest` directly — the booking payload should be passed under the `body` key, and optional `idempotencyKey` / `idempotencyError` headers can now be provided. Several new optional parameters have also been added: `labSlug` on `getMarkers`, `allowStale` on `getPscAppointmentAvailability`, `orderTransactionId` on `getOrders`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* The `address` field in `UserInfoCreateRequest` has changed its type from `Vital.Address` to `Vital.UserAddress` — callers passing an `Address` object will no longer compile and must update to `UserAddress`.
* The `teamId` optional property has been removed from `LinkListBulkOpsRequest` and from the bulk operation request bodies (`BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, `BulkPauseConnectionsBody`). Remove any `teamId` fields from calls to `listBulkOps`, `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause`.
* `ManualConnectionData` now accepts `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields which are forwarded as HTTP headers `x-vital-ios-sdk-version` and `x-vital-android-sdk-version` respectively.
* Several breaking type changes have been introduced in this release:
* **`ParsingJob.jobId` removed**: The `jobId` field has been removed from the `ParsingJob` interface. Remove any references to this field in your code.
* **`ResultMetadata` fields now optional**: `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`). Code that assumed these were always present will need null-checks.
* **`UserInfo.address` type changed**: The `address` field type changed from `Vital.Address` to `Vital.UserAddress`. Update type annotations and imports accordingly.
* **Boolean fields narrowed to literals**: `ClientFacingActivity.wheelchairUse`, `ClientFacingProfile.wheelchairUse`, `HistoricalPullCompleted.isFinal`, `UserRefreshSuccessResponse.success`, `UserRefreshErrorResponse.success`, and `Placeholder.placeholder` have been narrowed from `boolean` to specific literal types (`true` or `false`).
* New additions include: `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields on `ClientFacingInsulinInjectionSample`; a `failureReason` field on `ParsingJob`; new `OrderStatus` values for corrected results and lab processing blocked states; new provider values `samsung_health`, `tandem_source`, `sonora_quest`, and `crl`; and a new `compendium` serialization resource.
* The SDK introduces several new resource clients and API capabilities, but also includes breaking changes to existing types.
**Breaking changes:**
* `ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`). Code that previously accessed these as required strings must now handle `undefined`.
* `UserInfo.address` type has changed from `Address` to `UserAddress`. Update any code referencing `Address.Raw` in the context of `UserInfo` to use `UserAddress.Raw`.
* `UserRefreshSuccessResponse.success` is now typed as the literal `true`, and `UserRefreshErrorResponse.success` is now typed as the literal `false`. Code checking `success: boolean` may require type assertion updates.
**New capabilities:**
* New `client.compendium.search()` and `client.compendium.convert()` methods for lab compendium search and conversion.
* New `client.labAccount.getTeamLabAccounts()` method for retrieving team lab accounts.
* New `client.orderTransaction` resource client.
* New optional fields on `CreateLabTestRequest` (`labAccountId`, `labSlug`), `LabTestsGetMarkersRequest` (`labSlug`), `LabTestsGetOrdersRequest` (`orderTransactionId`), `RequestAppointmentRequest` (`appointmentNotes`), and `ManualConnectionData` (`vitalIosSdkVersion`, `vitalAndroidSdkVersion`, `grantedPermissions`).
* New `ResultMetadata.gender` optional field and new `LabTestsBookPscAppointmentRequest` type with idempotency key support.
* The SDK now includes a new `orderTransaction` client (accessible via `client.orderTransaction`) with methods to retrieve order transactions (`getTransaction`), their lab results (`getTransactionResult`), and PDF reports (`getTransactionResultPdf`). New types and enums have been added to support insulin injection timeseries data, order origins, order status details, derived readiness columns, lab accounts, and the Sonora Quest lab provider. Several existing types have been expanded with new optional fields, including `ClientFacingOrder`, `ClientFacingSleep`, `Address`, and `AppointmentBookingRequest`.
* The SDK now supports a wide range of new capabilities. New provider values `TandemSource` and `SamsungHealth` have been added to `Providers` (and `TandemSource` to `PasswordProviders`). Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) gain an optional `accessNotes` field. New types for compendium search (`SearchCompendiumResponse`, `SearchMode`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`), order transactions (`OrderSummary`, `OrderTransactionStatus`), and US states (`UsState`) are now available. Query expression union types (`QueryGroupByItem`, `QuerySelectItem`) now include `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr` variants. Appointment booking and rescheduling requests now accept optional `appointmentNotes` and async confirmation options.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New order transaction tracking types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderOrigin`, `OrderStatusDetail`) and optional fields (`clinicalNotes`, `lastEvent`, `origin`, `orderTransaction`) have been added to order-related models. New lab account management types (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`) and lab report parsing job webhook event types are now available. Additional sleep and readiness analytics types — including `DerivedReadinessColumnExpr` and a new `recoveryReadinessScore` field on `ClientFacingSleep` — have also been introduced.
* The SDK now includes many new types and capabilities. New lab compendium search types (`SearchCompendiumResponse`, `PerLabCandidate`, `RelatedCandidate`, `SearchMode`, `ProviderIdConversionResponse`) are available for working with lab marker search and crosswalk. All address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now support an optional `access_notes` field, and a new `UserAddress` type has been added. The `Providers` enum now includes `tandem_source` and `samsung_health`, and query expressions support new types including `AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, and `InsulinInjectionTimeseriesExpr`.
