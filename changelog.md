## 4.0.0 - 2026-04-13
* Several breaking changes have been made to the Link bulk operation request types and exported enums:
* The `teamId` optional property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any references to `teamId` in calls to these request types.
* The exported enum types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove any imports or usages of these types.
* `InsulinInjection` has been removed from the `IntervalTimeseriesExprTimeseries` enum.
* New values have been added: `sonora_quest` to `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `apero` and `pverify` to `PayorCodeExternalProvider`; `derived_readiness` to `IndexColumnExprIndex`.
* The `labReport.parserCreateJob` method now accepts an array of files (`core.file.Uploadable[]`) instead of a single file, enabling multi-file lab report parse jobs. Update existing calls by wrapping the single file argument in an array: `parserCreateJob([file], request)`. Three new resource namespaces are now available: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` instead of `AppointmentBookingRequest` directly — callers must wrap the existing booking payload in a `body` field and may optionally pass `idempotencyKey` and `idempotencyError` headers. Several new optional fields have also been added: `labSlug` on `getMarkers`, `allowStale` on `getPscAppointmentAvailability`, `orderTransactionId` on `getOrders`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* Several breaking changes have been made to request types in this release:
* The `teamId` field has been removed from `LinkListBulkOpsRequest` and from the bulk operation request bodies (`BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, `BulkPauseConnectionsBody`). Remove any `teamId` usage from these request objects — the server now infers it from context.
* The `address` field in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`. Update any code passing an `Address` object to use `UserAddress` instead.
* The `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields in `ManualConnectionData` are now sent as HTTP headers rather than body fields; existing callers that set these fields will automatically have them forwarded correctly.
* Several breaking type changes have been introduced in this release:
* **`ParsingJob.jobId`** (required `string`) has been removed. Callers accessing `job.jobId` must be updated. A new optional `failureReason` field has been added.
* **`ResultMetadata`** fields `patientFirstName`, `patientLastName`, `dob`, and `labName` have changed from required to optional (`string` → `string | undefined`). Code that accesses these without null-checks may need updating.
* **`UserInfo.address`** type has changed from `Address` to `UserAddress`. Callers passing or receiving this field must use the new type.
* Several boolean fields have been narrowed to literal types: `wheelchairUse?: true` (on `ClientFacingActivity` and `ClientFacingProfile`), `isFinal: true` (on `HistoricalPullCompleted`), `success: true` / `success: false` (on `UserRefreshSuccessResponse` / `UserRefreshErrorResponse`), and `placeholder: true`. Code checking these fields against `false` where the type was previously `boolean` will no longer compile.
* New additions include optional `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields on `ClientFacingInsulinInjectionSample`; new `OrderStatus` values for corrected results and lab-processing-blocked states; new lab values `sonora_quest` and `crl`; new provider values `samsung_health` and `tandem_source`; and a new `compendium` serialization resource.
* Three new API resource clients are now available on `VitalClient`:
* **`client.compendium`** — search and convert lab test compendium entries via `search()` and `convert()` methods.
* **`client.labAccount`** — retrieve team lab accounts via `getTeamLabAccounts()`.
* **`client.orderTransaction`** — new `OrderTransactionClient` for order transaction operations.
* Several existing request types have been extended with new optional fields: `CreateLabTestRequest` gains `labAccountId` and `labSlug`; `LabTestsGetMarkersRequest` gains `labSlug`; `LabTestsGetOrdersRequest` gains `orderTransactionId`; `RequestAppointmentRequest` gains `appointmentNotes`; and `ManualConnectionData` gains `vitalIosSdkVersion`, `vitalAndroidSdkVersion`, and `grantedPermissions`. The `ResultMetadata` type now includes an optional `gender` field and previously required fields (`patientFirstName`, `patientLastName`, `dob`, `labName`) are now optional.
* The SDK now includes a new `OrderTransactionClient` (accessible via `client.orderTransaction`) with methods to retrieve order transactions, their lab results, and PDF reports. Many new types have been added including `ClientFacingOrderTransaction`, `OrderTransactionStatus`, insulin injection timeseries types, readiness/recovery score support on `ClientFacingSleep`, and lab account management types. New enum values have been added for `SonoraQuest` lab/provider support, `InsulinPump` source type, `SamsungHealth` manual provider, and additional order low-level statuses. Note: `ClientFacingOrder` now includes a required `lastEvent` field.
* The SDK now includes new compendium search types (`SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`) and conversion types (`ConvertCompendiumResponse`, `ProviderIdConversionResponse`) for lab test lookups. New providers `TandemSource` and `SamsungHealth` have been added to `Providers`, and `Apero`/`Pverify` to `PayorCodeExternalProvider`. Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now support an optional `accessNotes` field, and appointment types support optional `appointmentNotes`. New query expression types (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, `InsulinInjectionTimeseriesExpr`) are available in `QueryGroupByItem`, `QuerySelectItem`, and `AggregateExprArg`. Order transaction and lab account types have also been introduced.
* The SDK now supports insulin pump as a source type across ECG, menstrual cycle, and sleep cycle data. New types and fields have been added for lab order transactions (`ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`), lab account management (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), compendium conversion (`ConvertCompendiumResponse`, `CompendiumSearchLabs`), and lab report parsing job webhook events. Additional optional fields have been added to `ClientFacingOrder` (`clinical_notes`, `last_event`, `origin`, `order_transaction`), `ClientFacingOrderEvent` (`status_detail`), `ClientFacingSleep` (`recovery_readiness_score`), and `ClientFacingInsulinInjectionSample` (`delivery_mode`, `delivery_form`, `bolus_purpose`).
* The SDK now supports new providers (`tandem_source` and `samsung_health`) in the `Providers` enum. New types have been added for lab compendium search (`SearchCompendiumResponse`, `SearchMode`, `PerLabCandidate`, `CanonicalCandidate`, `RelatedCandidate`), order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), and insulin injection timeseries expressions. Address types (`PatientAddress`, `UsAddress`, `UserAddress`) now include an optional `access_notes` field, and a new `UsState` enum is available.
