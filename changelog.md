## 4.0.0 - 2026-04-02
* Several breaking changes have been made to the SDK's type surface:
* The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed, along with the optional `teamId` property from their associated request interfaces (`BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`). Remove any references to these types and `teamId` fields from your code.
* The `InsulinInjection` value has been removed from `IntervalTimeseriesExprTimeseries`. Update any exhaustive checks over this enum accordingly.
* New enum values have been added: `SonoraQuest` to `AppointmentPscLabs` and `AppointmentProvider`, `sonora_quest` to `ClientFacingLabs`, `derived_readiness` to `IndexColumnExprIndex`, and `apero`/`pverify` to `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob` method now accepts an **array** of files (`file: core.file.Uploadable[]`) instead of a single file, enabling multi-file lab report uploads. Existing callers must wrap their single file argument in an array (e.g. `parserCreateJob([file], request)`).
* Three new resource namespaces are now available on the SDK client: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object (with the appointment booking payload nested under a `body` key) instead of `AppointmentBookingRequest` directly; callers must update their call sites accordingly. Several new optional request fields are also available: `allowStale` on `LabTestsGetPscAppointmentAvailabilityRequest`, `labSlug` on `LabTestsGetMarkersRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* The `teamId` optional parameter has been removed from `LinkListBulkOpsRequest` and the bulk operation request bodies (`BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, `BulkPauseConnectionsBody`) — remove this field from any existing calls to `listBulkOps`, `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause`. The `address` field in `UserInfoCreateRequest` has also changed its type from `Vital.Address` to `Vital.UserAddress` — update any TypeScript code that references the old type for this field.
* Several breaking changes are included in this release:
* **`ParsingJob.jobId` has been removed.** Update any code reading `parsingJob.jobId` — it no longer exists. A new optional `failureReason` field is available instead.
* **`ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional** (changed from required). Code that accessed these without null checks may now encounter `undefined`. A new optional `gender` field has also been added.
* **`UserInfo.address` type changed from `Address` to `UserAddress`.** Update any code that passes or receives an `Address` object in this field.
* Several boolean fields have been narrowed to literal types: `wheelchairUse` is now `true | undefined` (not `boolean | undefined`), `HistoricalPullCompleted.isFinal` is now `true`, `UserRefreshSuccessResponse.success` is now `true`, `UserRefreshErrorResponse.success` is now `false`, and `Placeholder.placeholder` is now `true`. Code relying on these as `boolean` may need type updates.
* New additions include optional `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields on `ClientFacingInsulinInjectionSample`; new `Labs` values (`sonora_quest`, `crl`); new `ManualProviders` value (`samsung_health`); new `PasswordProviders` value (`tandem_source`); new `OrderStatus` and `OrderLowLevelStatus` values for corrected and lab-processing-blocked states; and optional `grantedPermissions` on `ManualConnectionData`.
* The SDK introduces several breaking changes alongside new capabilities.
**Breaking changes:**
* `ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`). Code that previously accessed these as guaranteed strings will need null/undefined checks.
* `UserRefreshSuccessResponse.success` is now typed as the literal `true` (previously `boolean`), and `UserRefreshErrorResponse.success` is now typed as the literal `false`.
* `UserInfo` now uses `UserAddress` (instead of `Address`) for the `address` field in serialization.
**New features:**
* New `compendium` client on `VitalClient` with `search()` and `convert()` methods for lab test compendium search and cross-lab conversion.
* New `labAccount` client on `VitalClient` with `getTeamLabAccounts()` for retrieving team lab account details.
* New `orderTransaction` client on `VitalClient`.
* New optional parameters: `labAccountId`/`labSlug` on `CreateLabTestRequest`, `labSlug` on `LabTestsGetMarkersRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, `appointmentNotes` on `RequestAppointmentRequest`, and `vitalIosSdkVersion`/`vitalAndroidSdkVersion`/`grantedPermissions` on `ManualConnectionData`.
* The SDK now includes a new `orderTransaction` namespace on the client, exposing `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` methods for retrieving order transaction data and lab results. New types have been added for order transactions (`ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`), lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), and insulin injection timeseries data. Numerous existing types have been extended with new optional fields including `ClientFacingOrder.lastEvent`, `ClientFacingSleep.recoveryReadinessScore`, appointment notes fields, and new enum values for labs (`SonoraQuest`, `Crl`), providers (`SamsungHealth`), and order statuses.
* The SDK now includes support for order transactions (`OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), compendium search and conversion (`SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`), and lab account management (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`). New providers `TandemSource` and `SamsungHealth` have been added, along with new query expression types (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, `InsulinInjectionTimeseriesExpr`). Address types now support an optional `accessNotes` field, and appointment requests support optional `appointmentNotes` and async confirmation settings.
* The SDK now supports insulin pump as a device source type across multiple timeseries. New order transaction types (`ClientFacingOrderTransaction`, `OrderTransactionStatus`, `OrderOrigin`, `OrderStatusDetail`) are available, and `ClientFacingOrder` has new optional fields including `lastEvent`, `clinicalNotes`, `origin`, and `orderTransaction`. Lab account management types (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`) and lab report parsing job webhook event types are also introduced. The `ClientFacingInsulinInjectionSample` type now includes optional `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields, and `ClientFacingSleep` gains an optional `recoveryReadinessScore` field.
* The SDK now supports lab compendium search with new types including `SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. New order transaction types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderTransactionStatus`) and lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`) have been added. Address models (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now include an optional `access_notes` field, and two new provider values (`tandem_source`, `samsung_health`) have been added to the `Providers` enum.
