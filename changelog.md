## 4.0.0 - 2026-04-08
* Several breaking changes have been made to the Link bulk-operation request types and enum types.
**Removed exported types:** `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove any imports or references to these types from your code.
**Removed request fields:** The optional `teamId` property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Additionally, `insulin_injection` has been removed from `IntervalTimeseriesExprTimeseries`.
**New enum values added:** `sonora_quest` is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` has been added to `IndexColumnExprIndex`; and `apero` and `pverify` have been added to `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob` method now accepts an **array** of files (`core.file.Uploadable[]`) instead of a single file, enabling multi-file lab report parse jobs. Callers must update their code to wrap a single file in an array: `client.labReport.parserCreateJob([file], request)`.
* Three new resource namespaces are now available on the SDK: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method now accepts a `LabTestsBookPscAppointmentRequest` object instead of `AppointmentBookingRequest` directly. Callers must update their code to wrap the booking body under a `body` property (e.g. `{ body: { bookingKey: "..." } }`). Additionally, new optional fields have been added: `labSlug` on `LabTestsGetMarkersRequest`, `orderTransactionId` on the orders request, `allowStale` on `LabTestsGetPscAppointmentAvailabilityRequest`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* The `teamId` field has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody` — team identity is now inferred from context, so callers should remove any `teamId` usage from these request objects. Additionally, the `address` property in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`; update any code that constructs this request to use the new type.
* Several breaking type changes have been made in this release:
* **`ParsingJob`**: The `jobId` field has been removed. Update any code reading `parsingJob.jobId`.
* **`UserInfo.address`**: The type has changed from `Address` to `UserAddress`. Update type annotations and imports accordingly.
* **`ResultMetadata`**: `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`) instead of required strings. Add null checks where these fields are accessed.
* **`wheelchairUse`** on `ClientFacingActivity` and `ClientFacingProfile` is now typed as `true | undefined` instead of `boolean | undefined`; **`isFinal`** on `HistoricalPullCompleted` is now `true`; **`success`** on `UserRefreshSuccessResponse`/`UserRefreshErrorResponse` are now literal `true`/`false`. Code that assigns or compares these to `false`/`boolean` may need updating.
* New additions include optional `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields on `ClientFacingInsulinInjectionSample`; new `gender` field on `ResultMetadata`; `failureReason` on `ParsingJob`; new lab values (`sonora_quest`, `crl`), provider values (`samsung_health`, `tandem_source`), and new order statuses for corrected results and lab-processing-blocked states.
* The SDK now exposes three new resource clients on `VitalClient`: `compendium` (with `search()` and `convert()` methods for lab compendium lookup and cross-lab conversion), `labAccount` (with `getTeamLabAccounts()` for retrieving team lab accounts), and `orderTransaction`. Several existing request types have been extended with new optional fields, including `labAccountId`/`labSlug` on `CreateLabTestRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, `appointmentNotes` on `RequestAppointmentRequest`, and `grantedPermissions`/`vitalIosSdkVersion`/`vitalAndroidSdkVersion` on `ManualConnectionData`.
* The SDK now includes a new `OrderTransactionClient` (accessible as `client.orderTransaction`) with `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` methods for retrieving order transaction details and lab results. Numerous new types have been added, including insulin injection timeseries support, lab account management types (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), order transaction types (`ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`), and new webhook event types for lab report parsing jobs. New optional fields have been added to `AppointmentBookingRequest`, `AppointmentRescheduleRequest`, `ClientFacingAppointment`, `ClientFacingOrder`, `ClientFacingSleep`, and more. New enum values include `SonoraQuest` for labs and appointment providers, `SamsungHealth` for manual providers, `InsulinPump` for device source types, and several new order statuses.
* The SDK now supports compendium search and convert workflows with new types including `SearchCompendiumResponse`, `SearchMode`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. New order transaction types (`OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`) and lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`) are now available. Several existing types have been extended with new optional fields such as `accessNotes` on address types, `clinicalNotes` on order requests, and `appointmentNotes` on appointment requests/responses.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New types and fields are available for order transaction tracking (`ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`), lab account management (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), lab report parsing job webhook events, and compendium conversion responses. Existing types `ClientFacingOrder`, `ClientFacingOrderEvent`, `ClientFacingSleep`, `ClientFacingInsulinInjectionSample`, and `LabResultsRaw` have been extended with new optional fields.
* The SDK now includes new types for compendium search (`SearchCompendiumResponse`, `PerLabCandidate`, `RelatedCandidate`, `SearchMode`), provider ID conversion (`ProviderIdConversionResponse`), lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), and order transactions (`ClientFacingOrderTransaction`, `OrderSummary`, `OrderStatusDetail`). Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) now support an optional `access_notes` field, and the `Providers` enum has been extended with `tandem_source` and `samsung_health`. Query expression union types (`QuerySelectItem`, `QueryGroupByItem`) now include `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`.
