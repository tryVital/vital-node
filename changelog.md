## 4.0.0 - 2026-04-09
* Several breaking changes have been made to the Link bulk operation request types and exported enum types.
**Removed optional `teamId` properties:** The `teamId` field has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any `teamId` usage from these request objects.
**Removed exported types:** The following enum types have been deleted and are no longer exported: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`. Remove any references to these types in your code.
**Removed enum value:** `insulin_injection` has been removed from `IntervalTimeseriesExprTimeseries`. Update any exhaustive checks that reference this value.
**New enum values added:** `sonora_quest` is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` has been added to `IndexColumnExprIndex`; and `apero` and `pverify` have been added to `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob()` method now accepts an array of files (`core.file.Uploadable[]`) instead of a single file, enabling multiple files to be submitted in one parse job. Three new resource modules — `compendium`, `labAccount`, and `orderTransaction` — are now available on the SDK client.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object instead of `AppointmentBookingRequest` directly. Existing callers must wrap the booking payload in a `body` field (e.g. `{ body: { bookingKey: "..." } }`), and may optionally pass `idempotencyKey` and `idempotencyError` headers at the top level.
* Additional new optional parameters are also available: `labSlug` on `getMarkers`, `allowStale` on `getPscAppointmentAvailability`, `orderTransactionId` on `getOrders`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* The `teamId` property has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody` — remove any `teamId` usage from calls to these methods. Additionally, the `address` field in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`; update affected code accordingly.
* Several breaking changes are included in this release:
* **`ParsingJob.jobId` removed**: The required `jobId` field has been removed from `ParsingJob`. A new optional `failureReason` field (`ParsingJobFailureReason`) has been added in its place. Update any code reading `parsingJob.jobId`.
* **`UserInfo.address` type changed**: The `address` field type has changed from `Vital.Address` to `Vital.UserAddress`. Update type annotations and imports accordingly.
* **`ResultMetadata` fields now optional**: `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`). A new optional `gender` field has been added.
* **Literal type narrowing**: `wheelchairUse` on `ClientFacingActivity` and `ClientFacingProfile`, `isFinal` on `HistoricalPullCompleted`, `success` on `UserRefreshSuccessResponse`/`UserRefreshErrorResponse`, and `placeholder` on `Placeholder` are now narrowed to their literal values (`true` or `false`) rather than `boolean`.
* New additions include optional `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields on `ClientFacingInsulinInjectionSample`; new `sonora_quest` and `crl` lab values; `samsung_health` as a manual provider; `tandem_source` as a password provider; and new order status values including `corrected` variants and `lab_processing_blocked`.
* The SDK now exposes three new resource clients on `VitalClient`: `compendium` (with `search()` and `convert()` methods for lab test compendium lookup), `labAccount` (with `getTeamLabAccounts()`), and `orderTransaction`. Several existing request types gain new optional fields including `labSlug`, `labAccountId`, `orderTransactionId`, `appointmentNotes`, and idempotency key support for PSC appointment booking. `ResultMetadata` adds an optional `gender` field and relaxes previously required fields (`patientFirstName`, `patientLastName`, `dob`, `labName`) to optional.
* The SDK now includes a new `orderTransaction` resource on the client, exposing `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` methods for retrieving order transaction details and results. Numerous new types have been added including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, insulin injection timeseries types, and lab report parsing job events. Existing types such as `ClientFacingOrder`, `ClientFacingAppointment`, `AppointmentBookingRequest`, and `ClientFacingSleep` have been extended with new optional fields, and several enums (`AppointmentProvider`, `Labs`, `OrderStatus`, `ManualProviders`, etc.) have new values.
* The SDK now includes a broad set of new types and capabilities. New providers `TandemSource` and `SamsungHealth` are available in the `Providers` and `PasswordProviders` enums. Address types (`PatientAddress`, `UsAddress`, `UserAddress`, and others) now support an optional `accessNotes` field. New compendium search and conversion endpoints are supported via `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, and related types. Order transaction management is now available through `OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`, and `GetOrderTransactionResponse`. Lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`) and new query expression variants (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, `InsulinInjectionTimeseriesExpr`) have also been added.
* The SDK now supports insulin pump as a device source type, and exposes new optional fields on `ClientFacingInsulinInjectionSample` for delivery mode, delivery form, and bolus purpose. New types have been added for order transaction tracking (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab account management (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), and compendium conversion (`ConvertCompendiumResponse`, `CompendiumSearchLabs`). Additional optional fields (`origin`, `orderTransaction`, `clinicalNotes`, `lastEvent`, `statusDetail`, `recoveryReadinessScore`) have been added to existing order, order event, and sleep response types. New webhook event types for lab report parsing jobs are also included.
* The SDK now supports compendium search, lab accounts, and order transaction workflows via new types such as `SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, and `GetOrderTransactionResponse`. Address types (`PatientAddress`, `UsAddress`, `UserAddress`, etc.) now include an optional `access_notes` field. Two new providers — `tandem_source` and `samsung_health` — are available in the `Providers` enum, and several new query expression types (`DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`, `AwakeningsValueMacroExpr`) are supported in `QuerySelectItem` and `QueryGroupByItem`.
