## 4.0.0 - 2026-04-01
* Several breaking changes have been made to the Link bulk operation request types and exported enum types:
**Removed fields:** The optional `teamId` property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any `teamId` assignments from objects passed to these endpoints.
**Removed exported types:** The following exported enum types have been deleted and are no longer available: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`. Remove any imports or usages of these types from your code.
**Removed enum value:** `insulin_injection` has been removed from `IntervalTimeseriesExprTimeseries`. Update any code that references this value.
* New enum values have also been added: `sonora_quest` is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `apero` and `pverify` have been added to `PayorCodeExternalProvider`; and `derived_readiness` has been added to `IndexColumnExprIndex`.
* The `parserCreateJob` method on `LabReportClient` now accepts an array of files (`core.file.Uploadable[]`) instead of a single file (`core.file.Uploadable`), enabling multi-file lab report uploads. Callers must update their code to wrap the single file argument in an array (e.g. `parserCreateJob([file], request)`). Three new resource namespaces — `compendium`, `labAccount`, and `orderTransaction` — are now available on the client.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object (wrapping the booking body alongside optional `idempotencyKey` and `idempotencyError` header fields) instead of a bare `AppointmentBookingRequest`. The `getPscAppointmentAvailability` method gains a new optional `allowStale` flag to allow cached availability data to be returned. Additional optional fields have been added: `labSlug` on `getMarkers`, `orderTransactionId` on `getOrders`, and `clinicalNotes` on `CreateOrderRequestCompatible`.
* Several breaking changes have been made to request types in this release:
* The `teamId` property has been removed from `LinkListBulkOpsRequest`, `BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, and `BulkPauseConnectionsBody`. Remove any usage of `teamId` from calls to `listBulkOps`, `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause`.
* The `address` field in `UserInfoCreateRequest` has changed type from `Vital.Address` to `Vital.UserAddress`. Update any code constructing this request to use the `UserAddress` type.
* The `connectManual` method now expects `vitalIosSdkVersion` and `vitalAndroidSdkVersion` to be passed as properties on the request object (sent as HTTP headers), rather than as body fields in `ManualConnectionData`.
* Several breaking changes have been made to SDK types in this release:
* **`ParsingJob`**: The `jobId` field has been removed. Update any code reading `parsingJob.jobId` to use alternative identifiers. A new optional `failureReason` field has been added.
* **`ResultMetadata`**: The previously required fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`). Add null checks when accessing these fields. A new optional `gender` field has also been added.
* **`UserInfo.address`**: The type has changed from `Address` to `UserAddress`. Update any code that references the `Address` type for this field.
* **Boolean literals narrowed**: `wheelchairUse` on `ClientFacingActivity` and `ClientFacingProfile`, `isFinal` on `HistoricalPullCompleted`, `success` on `UserRefreshSuccessResponse` and `UserRefreshErrorResponse`, and `placeholder` on `Placeholder` have all been narrowed from `boolean` to specific literal types (`true` or `false`). Existing code assigning `false` to `wheelchairUse` or `isFinal` will no longer compile.
* New additions include insulin injection delivery fields (`deliveryMode`, `deliveryForm`, `bolusPurpose`) on `ClientFacingInsulinInjectionSample`, new order statuses for corrected results and lab processing blocks, new lab (`sonora_quest`, `crl`), manual (`samsung_health`), and password (`tandem_source`) provider values, and a new `compendium` serialization resource.
* The SDK introduces several breaking changes alongside new features.
**Breaking changes:**
* `ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | null | undefined` instead of `string`). Code that accesses these fields without null checks will no longer be type-safe.
* `UserInfo.address` type has changed from `Address` to `UserAddress`. Code referencing `Address.Raw` on this field must be updated to `UserAddress.Raw`.
* `UserRefreshErrorResponse.success` is now narrowed to the literal type `false` (was `boolean`), and `UserRefreshSuccessResponse.success` is now narrowed to `true` (was `boolean`). Exhaustive type checks on these fields may need updating.
**New features:**
* Three new resource clients are now available on `VitalClient`: `client.compendium` (with `search()` and `convert()` methods), `client.labAccount` (with `getTeamLabAccounts()`), and `client.orderTransaction`.
* `CreateLabTestRequest`, `LabTestsGetMarkersRequest`, `LabTestsGetOrdersRequest`, `RequestAppointmentRequest`, and `ManualConnectionData` each gain new optional fields for extended configuration and filtering.
* The SDK now includes a new `orderTransaction` client (`client.orderTransaction`) with methods to retrieve order transactions (`getTransaction`), their raw lab results (`getTransactionResult`), and result PDFs (`getTransactionResultPdf`). Numerous new types have been added including `ClientFacingOrderTransaction`, `OrderOrigin`, `OrderStatusDetail`, `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`, `AwakeningsValueMacroExpr`, `ClientFacingLabAccount`, and lab report parsing job event types. Existing types have been expanded with new optional fields (e.g. `ClientFacingOrder.lastEvent`, `ClientFacingSleep.recoveryReadinessScore`, `Address.accessNotes`) and new enum values have been added across `AppointmentProvider`, `Labs`, `ManualProviders`, `OrderStatus`, `OrderLowLevelStatus`, and several source type enums.
* The SDK now includes new compendium search and conversion capabilities (`SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`) along with order transaction support (`OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`, `GetOrderTransactionResponse`) and lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`). New providers `TandemSource` and `SamsungHealth` have been added to the `Providers` and `PasswordProviders` enums, and new payor code providers `Apero` and `Pverify` have been added to `PayorCodeExternalProvider`. Several address types now include an optional `accessNotes` field, and query expressions now support `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`.
* The SDK now supports insulin pump as a device source type, and introduces new optional fields on `ClientFacingInsulinInjectionSample` (`deliveryMode`, `deliveryForm`, `bolusPurpose`). New types for order transactions (`ClientFacingOrderTransaction`, `OrderTransactionStatus`, `OrderOrigin`, `OrderSummary`), lab accounts (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), lab report parsing job events, compendium conversion (`ConvertCompendiumResponse`, `CompendiumSearchLabs`), and readiness analytics (`DerivedReadinessColumnExpr`) are now available. Additional optional fields have been added to `ClientFacingOrder` (`lastEvent`, `clinicalNotes`, `origin`, `orderTransaction`), `ClientFacingOrderEvent` (`statusDetail`), `ClientFacingSleep` (`recoveryReadinessScore`), and `LabResultsRaw` (`orderTransaction`).
* The SDK now includes a range of new types and fields. New compendium search capabilities are available via `SearchCompendiumResponse`, `SearchMode`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. Order management is expanded with `ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderStatusDetail`, and related types. Address types (`PatientAddress`, `UsAddress`, `UserAddress`, and variants) now support an optional `access_notes` field, and the `Providers` enum includes two new values: `tandem_source` and `samsung_health`.
