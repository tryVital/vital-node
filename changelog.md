## 4.0.0 - 2026-04-07
* Several breaking changes have been made to the Link bulk operation request types and exported enums:
* The `teamId` optional property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any usage of this field from request objects.
* The exported enum types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove all imports and references to these types.
* The `insulin_injection` value has been removed from the `IntervalTimeseriesExprTimeseries` enum.
* New enum values have also been added: `sonora_quest` is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` has been added to `IndexColumnExprIndex`; and `apero` and `pverify` have been added to `PayorCodeExternalProvider`.
* The `labReport.parserCreateJob` method now accepts an array of files (`Uploadable[]`) instead of a single file (`Uploadable`), enabling multi-file lab report uploads. Three new resource modules are now available: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` instead of `AppointmentBookingRequest`. Migrate by wrapping the booking body under a `body` field: `{ body: { bookingKey: "..." } }`. The new request type also supports optional `idempotencyKey` and `idempotencyError` fields for idempotent requests. Several new optional fields have also been added: `allowStale` on `LabTestsGetPscAppointmentAvailabilityRequest`, `orderTransactionId` on order search requests, `clinicalNotes` on `CreateOrderRequestCompatible`, and `labSlug` on `LabTestsGetMarkersRequest`.
* Several breaking changes have been made to the `LinkClient` and related request types:
* The `teamId` field has been removed from `LinkListBulkOpsRequest` and the request bodies for `bulkImport`, `bulkTriggerHistoricalPull`, `bulkExport`, and `bulkPause`. Remove this field from any calls to these methods.
* The `address` field in `UserInfoCreateRequest` has changed its type from `Vital.Address` to `Vital.UserAddress`. Update any code constructing this request to use `Vital.UserAddress`.
* In `ManualConnectionData`, the `vitalIosSdkVersion` and `vitalAndroidSdkVersion` fields are now sent as HTTP request headers (`x-vital-ios-sdk-version` / `x-vital-android-sdk-version`) rather than as body properties.
* Several breaking type changes have been introduced in this release.
* `ParsingJob.jobId` (required `string`) has been removed; access `failureReason` (optional) instead.
* `UserInfo.address` now uses the `UserAddress` type instead of `Address` — update any code referencing `Vital.Address` in this context.
* `ResultMetadata` fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | undefined`) rather than required; update any code that assumed these fields were always present.
* `wheelchairUse` on `ClientFacingActivity` and `ClientFacingProfile`, `isFinal` on `HistoricalPullCompleted`, `success` on `UserRefreshErrorResponse`/`UserRefreshSuccessResponse`, and `placeholder` on `Placeholder` have been narrowed to literal types (`true` or `false`) — callers performing strict type comparisons may be affected.
* New additions include `ClientFacingInsulinInjectionSample.deliveryMode`, `deliveryForm`, and `bolusPurpose` fields, new `Labs`, `OrderStatus`, `OrderLowLevelStatus`, `ManualProviders`, and `PasswordProviders` enum values, a new `compendium` resource, and `grantedPermissions` on `ManualConnectionData`.
* **Breaking:** The `ResultMetadata` type has changed — the fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional (`string | null | undefined`). Callers that accessed these fields without null checks will receive TypeScript type errors and must add appropriate guards. The `UserInfo.address` field type has also changed from `Address` to `UserAddress`; update any code referencing `Address.Raw` in this context.
**New:** Three new resource clients are now available on `VitalClient`:
* `client.compendium` — search and convert lab compendium entries
* `client.labAccount` — retrieve team lab accounts
* `client.orderTransaction` — access order transaction data
* Several existing request types have gained new optional fields, including `labAccountId`/`labSlug` on `CreateLabTestRequest`, `orderTransactionId` on `LabTestsGetOrdersRequest`, `appointmentNotes` on `RequestAppointmentRequest`, and SDK version/permission fields on `ManualConnectionData`.
* The SDK now includes a new `orderTransaction` client (accessible via `client.orderTransaction`) with `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` methods for retrieving order transaction details and results. New types have been added for insulin injection timeseries data, lab accounts, order transactions, parsing job events, and derived readiness analytics. Several existing types such as `ClientFacingOrder`, `ClientFacingAppointment`, `ClientFacingSleep`, and `AppointmentBookingRequest` have been extended with new optional fields, and multiple enums have been expanded with new values including `SonoraQuest`, `InsulinPump`, `SamsungHealth`, and additional order statuses.
* The SDK now supports compendium search and conversion with new `SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ConvertCompendiumResponse`, and `SearchMode` types. New providers `TandemSource` and `SamsungHealth` have been added, along with order transaction types (`OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`), extended address types with an optional `accessNotes` field, and new query expression variants (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, `InsulinInjectionTimeseriesExpr`). Appointment booking and rescheduling now support optional `appointmentNotes` and async confirmation fields.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New fields have been added to `ClientFacingInsulinInjectionSample` (delivery mode, delivery form, bolus purpose), `ClientFacingSleep` (recovery readiness score), and `ClientFacingOrder` (clinical notes, origin, order transaction, last event). New types are available for order transaction tracking (`ClientFacingOrderTransaction`, `OrderTransactionStatus`, `OrderOrigin`), lab account management (`ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`), lab report parsing job events, and compendium conversion responses.
* The SDK now includes a large set of new types and capabilities. Compendium search is supported via `SearchCompendiumResponse`, `SearchMode`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. Order transaction tracking is available through `ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, and related types. Lab account management is supported with `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountStatus`, and `LabAccountDelegatedFlow`. Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`, and the new `UserAddress`) now include an optional `access_notes` field. Two new providers—`tandem_source` and `samsung_health`—have been added to the `Providers` enum, and new query expression types (`InsulinInjectionTimeseriesExpr`, `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`) are available for use in select and group-by queries.
