## 4.0.0 - 2026-04-01
* Several breaking changes have been made to the Link bulk operation request types and exported enum types.
**Removed properties:** The optional `teamId` field has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any references to `teamId` in calls to these APIs.
**Removed types:** The exported enum types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove any imports or usages of these types.
**Removed enum value:** `insulin_injection` has been removed from `IntervalTimeseriesExprTimeseries`. Update any exhaustive checks that reference this value.
**New enum values added:** `sonora_quest` is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` in `IndexColumnExprIndex`; and `apero`/`pverify` in `PayorCodeExternalProvider`.
* The `parserCreateJob` method on `LabReportClient` now accepts an array of files (`core.file.Uploadable[]`) instead of a single file (`core.file.Uploadable`), enabling multi-file lab report parse jobs. Existing callers must wrap their single file argument in an array (e.g. `parserCreateJob([file], request)`). Three new resource namespaces are also available: `compendium`, `labAccount`, and `orderTransaction`.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object instead of `AppointmentBookingRequest` directly. The new request type wraps the booking body under a `body` property and adds optional `idempotencyKey` and `idempotencyError` header fields. Callers must update their code to pass `{ body: { bookingKey: "..." } }` instead of `{ bookingKey: "..." }`.
* Several methods also gain new optional parameters: `getMarkers` now accepts `labSlug`, `getOrders` now accepts `orderTransactionId`, `getPscAppointmentAvailability` now accepts `allowStale`, and `CreateOrderRequestCompatible` now includes an optional `clinicalNotes` field.
* The `teamId` property has been removed from `LinkListBulkOpsRequest` and related bulk operation request types (`BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, `BulkPauseConnectionsBody`). The `address` field in `UserInfoCreateRequest` now expects `Vital.UserAddress` instead of `Vital.Address` — callers must update their type references accordingly. Additionally, `vitalIosSdkVersion` and `vitalAndroidSdkVersion` are no longer sent as body fields in `ManualConnectionData` but are now automatically forwarded as HTTP headers (`x-vital-ios-sdk-version`, `x-vital-android-sdk-version`).
* Several breaking changes are included in this release alongside new features. The `success` field on `UserRefreshSuccessResponse.Raw` and `UserRefreshErrorResponse.Raw` has been narrowed from `boolean` to the literal types `true` and `false` respectively — callers that assigned a general `boolean` to these fields will need to update their types. The `address` field in `UserInfo` now uses `UserAddress.Raw` instead of `Address.Raw`; callers referencing `Address.Raw` for this property must migrate to `UserAddress.Raw`. Previously required fields `patientFirstName`, `patientLastName`, `dob`, and `labName` on `ResultMetadata` are now optional.
* New capabilities: Three new resource clients are available on `VitalClient` — `client.compendium` (with `search()` and `convert()` methods), `client.labAccount` (with `getTeamLabAccounts()`), and `client.orderTransaction`. Additional optional fields have been added to `CreateLabTestRequest`, `LabTestsGetMarkersRequest`, `LabTestsGetOrdersRequest`, `RequestAppointmentRequest`, and `ManualConnectionData`.
* The SDK now includes a new `OrderTransactionClient` (accessible as `client.orderTransaction`) with three methods: `getTransaction`, `getTransactionResult`, and `getTransactionResultPdf` for retrieving order transaction details, raw lab results, and PDF reports respectively.
* Numerous existing types have been expanded with new optional fields, including `ClientFacingOrder` (adds `clinicalNotes`, `lastEvent`, `origin`, `orderTransaction`), `ClientFacingSleep` (adds `recoveryReadinessScore`), `ClientFacingAppointment` (adds `orderTransactionId`, `appointmentNotes`), and `AppointmentBookingRequest` (adds async confirmation controls). New types are also available for insulin injection timeseries data, lab accounts, lab report parsing job events, derived readiness expressions, and order transaction lifecycle tracking.
* The SDK now supports compendium search and conversion capabilities with new types including `SearchCompendiumResponse`, `SearchMode`, `CanonicalCandidate`, `PerLabCandidate`, and `RelatedCandidate`. Order transaction management is now available via `OrderSummary`, `OrderTransactionStatus`, `ClientFacingOrderTransaction`, and related types. Several existing request types (`PatientAddress`, `UsAddress`, `AppointmentBookingRequest`, `AppointmentRescheduleRequest`, `CreateOrderRequestCompatible`) have been expanded with new optional fields such as `accessNotes`, `appointmentNotes`, and `clinicalNotes`. New providers `TandemSource` and `SamsungHealth` are now available in the `Providers` enum, and `Apero` and `Pverify` have been added to `PayorCodeExternalProvider`.
* The SDK now supports several new capabilities:
* **Insulin pump** is available as a new device source type across all relevant source-type enums.
* **Insulin injection samples** now expose optional `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields with corresponding enum types.
* **Order transactions** are introduced via `ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, and related types. `ClientFacingOrder` gains optional `clinicalNotes`, `lastEvent`, `origin`, and `orderTransaction` fields; `ClientFacingOrderEvent` gains an optional `statusDetail` field.
* **Lab accounts** are now represented by `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, and supporting enums (`LabAccountStatus`, `LabAccountDelegatedFlow`).
* **Lab report parsing events** (`ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent`) are now available.
* **Compendium conversion** support is added via `ConvertCompendiumResponse` and `CompendiumSearchLabs`.
* `ClientFacingSleep` now includes an optional `recoveryReadinessScore` field.
* New readiness and insulin injection analytics expression types (`DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`, and related field enums) are available.
* The SDK now supports a range of new types and capabilities. New compendium search types (`SearchCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `SearchMode`) enable lab test lookup workflows. New order transaction types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderTransactionStatus`) and lab account types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`) are now available. Address types (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) gain an optional `accessNotes` field, and two new providers (`tandem_source`, `samsung_health`) have been added to the `Providers` enum. Query expression unions now include `InsulinInjectionTimeseriesExpr`, `DerivedReadinessColumnExpr`, and `AwakeningsValueMacroExpr`.
