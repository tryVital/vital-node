## 4.0.0 - 2026-04-02
* Several breaking changes have been made to the Link bulk operation request types and related exported symbols:
* The optional `teamId` property has been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, and `BulkTriggerHistoricalPullBody`. Remove any references to `teamId` in calls to these request types.
* The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been deleted. Remove any imports or usages of these types.
* The `insulin_injection` value has been removed from the `IntervalTimeseriesExprTimeseries` enum.
* New enum values have also been added: `SonoraQuest` (`"sonora_quest"`) is now available in `AppointmentPscLabs`, `AppointmentProvider`, and `ClientFacingLabs`; `derived_readiness` has been added to `IndexColumnExprIndex`; and `apero` and `pverify` have been added to `PayorCodeExternalProvider`.
* The `parserCreateJob` method on `LabReportClient` now accepts an array of files (`core.file.Uploadable[]`) instead of a single file. Callers must wrap their existing single-file argument in an array (e.g., `parserCreateJob([file], request)` instead of `parserCreateJob(file, request)`).
* Three new resource namespaces are now available: `compendium`, `labAccount`, and `orderTransaction`, accessible from the top-level SDK client.
* The `bookPscAppointment` method on `LabTestsClient` now accepts a `LabTestsBookPscAppointmentRequest` object (with the booking payload under a `body` key) instead of `AppointmentBookingRequest` directly; callers must update their invocations accordingly. Additionally, several new optional fields have been added: `allowStale` on `LabTestsGetPscAppointmentAvailabilityRequest`, `clinicalNotes` on `CreateOrderRequestCompatible`, `labSlug` on `LabTestsGetMarkersRequest`, and `orderTransactionId` on the `getOrders` request — all backward-compatible additions.
* The `teamId` property has been removed from `LinkListBulkOpsRequest` and the bulk operation request bodies (`BulkImportConnectionsBody`, `BulkTriggerHistoricalPullBody`, `BulkExportConnectionsBody`, `BulkPauseConnectionsBody`). Callers passing `teamId` should remove it — team context is now inferred automatically by the server. Additionally, the `address` field in `UserInfoCreateRequest` has changed its type from `Vital.Address` to `Vital.UserAddress`; update any usages accordingly.
* Several breaking type changes have been introduced in this release:
* **`ParsingJob`**: The `jobId` field has been removed. Code that reads `parsingJob.jobId` must be updated. A new optional `failureReason` field is now available.
* **`UserInfo` / `UserInfoCreateRequest`**: The `address` field type has changed from `Address` to `UserAddress`. Callers constructing or consuming this type must use `UserAddress`.
* **`ResultMetadata`**: The previously required fields `patientFirstName`, `patientLastName`, `dob`, and `labName` are now optional. Code that treats these as always-present will need null/undefined guards. A new optional `gender` field is also available.
* **`wheelchairUse`** in `ClientFacingActivity` and `ClientFacingProfile`, **`isFinal`** in `HistoricalPullCompleted`, **`success`** in `UserRefreshErrorResponse`/`UserRefreshSuccessResponse`, and **`placeholder`** in `Placeholder` have been narrowed from `boolean` to literal `true` or `false` types — callers relying on the broader `boolean` type in exhaustive checks may need updates.
* New additions include `deliveryMode`, `deliveryForm`, and `bolusPurpose` fields on `ClientFacingInsulinInjectionSample`; new lab values (`sonora_quest`, `crl`); new provider values (`samsung_health`, `tandem_source`); and new order statuses (`corrected`, `lab_processing_blocked`).
* Three new clients are now available on `VitalClient`: `compendium` (with `search()` and `convert()` methods), `labAccount` (with `getTeamLabAccounts()`), and `orderTransaction`. Several request types have gained new optional fields (`labAccountId`, `labSlug`, `orderTransactionId`, `appointmentNotes`, `grantedPermissions`, etc.).
**Breaking changes:** Previously required fields on `ResultMetadata` (`patientFirstName`, `patientLastName`, `dob`, `labName`) are now optional (`string | undefined`), which changes their TypeScript types and may require null-checks in existing code. The `address` field on `UserInfo` has changed type from `Address.Raw` to `UserAddress.Raw`. The `success` field on `UserRefreshErrorResponse` is now narrowed to the literal type `false` (previously `boolean`), and on `UserRefreshSuccessResponse` to the literal `true`. Callers relying on these types without code changes may encounter compile errors.
* The SDK now includes a new `OrderTransactionClient` (accessible via `client.orderTransaction`) with methods to retrieve order transactions (`getTransaction`), raw lab results (`getTransactionResult`), and PDF lab results (`getTransactionResultPdf`). Sonora Quest has been added as a supported lab and appointment provider. Numerous new optional fields have been added to existing types such as `ClientFacingOrder`, `ClientFacingAppointment`, and `Address`, along with new types for insulin injection timeseries, derived readiness metrics, order origins, order status details, lab accounts, and lab report parsing job events.
* The SDK now includes support for compendium search and crosswalk via new `SearchCompendiumResponse`, `ConvertCompendiumResponse`, and related candidate types. Order transaction management is available through new `OrderSummary`, `OrderTransactionStatus`, and `ClientFacingOrderTransaction` types, and lab account management is supported via `ClientFacingLabAccount` and related types. New providers (`TandemSource`, `SamsungHealth`), query expression types (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, `InsulinInjectionTimeseriesExpr`), and optional fields such as `accessNotes` on address types and `appointmentNotes` on appointment requests have also been added.
* The SDK now supports insulin pump as a device source type across all relevant source type enums. New order transaction types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderSummary`, `OrderOrigin`, `OrderStatusDetail`) and lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`) have been added. Additional optional fields are available on `ClientFacingOrder` (`origin`, `order_transaction`, `clinical_notes`, `last_event`), `ClientFacingOrderEvent` (`status_detail`), `ClientFacingInsulinInjectionSample` (`delivery_mode`, `delivery_form`, `bolus_purpose`), `ClientFacingSleep` (`recovery_readiness_score`), and `LabResultsRaw` (`order_transaction`). New webhook event types for lab report parsing jobs (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`) and new compendium conversion types (`ConvertCompendiumResponse`, `CompendiumSearchLabs`) are also included.
* The SDK now supports several new capabilities: lab compendium search (`SearchCompendiumResponse`, `SearchMode`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`), order transaction tracking (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`, `OrderTransactionStatus`), and provider ID conversion (`ProviderIdConversionResponse`). New providers `tandem_source` and `samsung_health` have been added to the `Providers` enum, and address types now support an optional `access_notes` field. New query expression types (`AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`) are now available for use in `QueryGroupByItem` and `QuerySelectItem`.
